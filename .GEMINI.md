# GEMINI.md - Contexto y Guía de Arquitectura para Modelos de IA

Este documento describe la arquitectura, decisiones de diseño, modelos de datos y convenciones de este repositorio para que cualquier modelo de Inteligencia Artificial (LLM / Agente) pueda operar, extender o depurar el sistema con total precisión.

---

## 🧠 Propósito y Contexto del Repositorio

El proyecto **DashboardHRV** es una herramienta clínica y de análisis fisiológico para procesar reportes de Variabilidad de la Frecuencia Cardíaca (HRV) generados por el software **Kubios HRV**, estructurados en un protocolo estandarizado de 6 fases (DS, RC10, RC12, ORT, RUFF, REC).

### Principios Fundamentales de Diseño
1. **Zero-Server / Offline First**: El Dashboard debe poder abrirse localmente con un doble clic (`file:///...`) sin requerir `npm`, `node`, `python -m http.server` ni backend activo.
2. **Bypass de CORS**: Debido a las restricciones de seguridad de los navegadores al cargar archivos JSON locales con `fetch()`, el script de Python genera tanto `data.json` como `data.js` (este último exporta `const patientData = {...};`). El HTML carga `<script src="data_dinamica/data.js"></script>`.
3. **Paciente Único Activo en Carpeta `data_dinamica/`**: El Dashboard siempre lee los datos en la carpeta `data_dinamica/` (`data_dinamica/data.js` y `data_dinamica/data.json`). El script de Python actúa como el "conmutador", copiando la información del paciente procesado a `data_dinamica/` y dejando un archivo `data_dinamica/activo.txt` que indica a quién pertenece la ejecución activa.
4. **Supervisión Médica Obligatoria**: Las conclusiones clínicas no se publican en el dashboard de forma automática sin el visto bueno explícito del médico (controlado mediante el flag `REVISADO: SI / NO` en archivos `_conclusiones.txt`).
5. **Separación de Plantillas**: Las narrativas y estructuras de referencia se almacenan de forma desacoplada en `plantillas/plantilla_conclusiones.md`.

## 🏗️ Arquitectura y Componentes

### 1. `scripts/parse_hrv.py` (Motor de Procesamiento)
Script en Python 3 puro (sin dependencias externas pesadas, solo bibliotecas estándar: `os`, `sys`, `json`, `re`, `datetime`).

* **Extracción de Métricas**:
  Parsea líneas de texto del reporte CSV de Kubios para extraer las 12 métricas fundamentales de cada una de las 6 fases:
  * PNS Index, SNS Index, Mean HR, RMSSD, LF/HF ratio, SD1, SD2, VLF (%), LF (%), HF (%), SDNN, Stress Index.
* **Manejo de Conclusiones (`_conclusiones.txt`)**:
  * Si no existe el archivo `.txt` para una fecha `DDMMYYYY.csv`, genera la plantilla pre-llenada con `REVISADO: NO`.
  * Lee el archivo y busca la cabecera `REVISADO: SI` (insensible a mayúsculas, tildes o variantes en inglés).
  * Asigna `"reviewed": true / false` en la estructura de datos.
* **Modos de Ejecución**:
  * **Modo Carpeta (`is_full_scan=True`)**: La carpeta es la fuente de la verdad. Reconstruye el `data.json` local eliminando sesiones cuyos CSV hayan sido borrados y limpiando archivos `.txt` huérfanos.
  * **Modo Archivo Individual (`is_full_scan=False`)**: Añade o actualiza únicamente esa sesión en el `data.json` sin alterar las demás.
  * **Soporte de Entradas**: Acepta carpetas de paciente, archivos `.csv` o archivos `_conclusiones.txt`.

### 2. `dashboard.html` (Frontend Dinámico)
Documento HTML5/CSS3/JavaScript interactivo sin librerías externas (Vanilla JS y SVG puro).

* **Header, Selector de Sesión y KPIs**:
  * Renderiza dinámicamente el nombre del paciente (`patientData.patient_name`), la fecha de la sesión evaluada y el contador global de sesiones.
  * **Selector Interactivo (`#session-select`)**: Permite al usuario cambiar entre cualquier sesión del historial sin recargar la página; dispara `loadSessionEvaluation(index)` que refresca en caliente los 4 KPIs, la tabla cuantitativa, las conclusiones auditadas y los gráficos de la Pestaña 1, manteniendo intacta la pestaña Longitudinal.
  * Muestra la fecha en el botón de la pestaña: `Evaluación de la Sesión (DD/MM/AAAA)`.
* **Badge de Estado Clínico Superior Derecho (`#patient-status-badge`)**:
  * Calculado en base a los índices basales de reposo (Fase 1: DS):
    * `SNS > 2.0` ➔ `● Estado de Estrés Simpático` (Rojo).
    * `PNS < -2.0` ➔ `● Tono Vagal Deprimido` (Ámbar).
    * `PNS > 2.0 y SNS < -2.0` ➔ `● Predominio Vagal Basal` (Celeste).
    * En rango normal $[-2.0, 2.0]$ ➔ `● Flexibilidad Autonómica Normal` (Verde).
* **Badge de Auditoría Médica (`#review-status-badge`)**:
  * Si `session.reviewed === true` ➔ `✓ Conclusiones Validadas por Médico` (Verde) y muestra el texto.
  * Si `session.reviewed === false` ➔ `⏳ Pendiente de Revisión Médica` (Ámbar) y muestra *"No se ha realizado el análisis"*.
* **Pestaña Longitudinal (Línea Base)**:
  * Si $N < 7$ sesiones: Muestra advertencia de datos insuficientes y representa únicamente los puntos de datos individuales (oculta la banda y la media).
  * Si $N \ge 7$ sesiones: Oculta la advertencia y calcula dinámicamente la banda de normalidad (SWC: Media móvil 7d $\pm 0.5\text{ SD}$) y la línea verde de tendencia para los 6 gráficos de fase.
* **Exportación a PDF / Impresión (`@media print`)**:
  * Orquesta un **Dossier Clínico Maestro de 4 páginas A4** con fondo claro (*Light Mode*):
    * **Pág. 1**: Header, KPIs y 4 gráficos de sesión (`.charts-grid` con `page-break-after: always`).
    * **Pág. 2**: Tabla de 6 fases y 3 conclusiones auditadas (`.interpretation-grid` con `page-break-after: always`).
    * **Pág. 3**: `.longitudinal-block-1` con Fases 1, 2 y 3 (Fase 3 centrada, `page-break-after: always`).
    * **Pág. 4**: `.longitudinal-block-2` con Fases 4, 5 y 6 (Fase 6 centrada) y Nota metodológica SWC.
  * **Regla Crítica**: Los contenedores principales (`.container`, `.tab-content`) deben mantener `display: block !important` en impresión para que los motores WebKit/Blink ejecuten correctamente los saltos de página sin crear páginas en blanco ni desbordes.

### 3. `.agents/skills/parse-hrv/SKILL.md` (Custom Skill de Antigravity)
Define la skill `/parse-hrv` para que el asistente de IA sepa cómo interactuar con el parser ante comandos del usuario.

## 📌 Guía para Futuras Modificaciones (Instrucciones para el Agente)

1. **Nunca romper la compatibilidad CORS**: Mantener siempre la exportación sincronizada de `data.json` y `data.js`.
2. **Respetar la convención de nombres**:
   * Carpetas de pacientes: `Pacientes/<NombrePaciente>_HRV/`
   * Archivos CSV: `DDMMYYYY.csv` (ej. `31082026.csv`)
   * Archivos de conclusiones: `DDMMYYYY_conclusiones.txt`
3. **Comandos Clave**:
   * Reconstruir paciente: `python3 scripts/parse_hrv.py Pacientes/<Carpeta>/`
   * Procesar sesión: `python3 scripts/parse_hrv.py Pacientes/<Carpeta>/DDMMYYYY.csv`
4. **Estilo de Código**: Mantener el código JavaScript en `dashboard.html` limpio, modular y con control de excepciones para evitar caídas si un paciente tiene datos parciales o nulos.
